### Прецедент: Запуск тестовой сессии (RunTestSession)

**Описание:**  
Разработчик (Developer) инициирует запуск автоматической тестовой сессии через систему автоматического тестирования. Процесс включает следующие шаги:

1. Разработчик выбирает тест-сьют для выполнения.
2. Система проверяет доступность тестовой среды и необходимых ресурсов.
3. Разработчик настраивает параметры запуска (окружение, конфигурацию, тестовые данные).
4. Система запускает выполнение тест-кейсов в выбранном окружении.
5. Во время выполнения система собирает результаты и логи.
6. После завершения система формирует детализированный отчет.
7. Разработчик получает уведомление о завершении тестовой сессии.

---

**Актёры:**

- **Разработчик (Developer)**: инициирует запуск тестов, настраивает параметры, просматривает результаты.
- **Система автоматического тестирования (TestController)**: управляет процессом запуска и выполнения тестов.
- **Менеджер среды (EnvironmentManager)**: управляет тестовыми окружениями.
- **TestRunner**: выполняет тест-кейсы.
- **Менеджер ресурсов (ResourceManager)**: выделяет и освобождает ресурсы для тестов.
- **Генератор отчетов (ReportGenerator)**: формирует отчеты о результатах тестирования.
- **CI/CD система (CISystem)**: может инициировать запуск тестов автоматически.

---

**Предусловия:**

- Разработчик имеет доступ к системе и права на запуск тестов.
- Тест-сьют и тестовые данные доступны в репозитории.
- Доступна хотя бы одна тестовая среда для выполнения тестов.
- Система подключена к необходимым внешним системам (CI/CD, репозитории).

---

**Постусловия:**

- Тест-кейсы выполнены.
- Результаты тестирования собраны и проанализированы.
- Отчет о тестировании сформирован и доступен.
- Ресурсы освобождены (если не требуется сохранение среды для отладки).

---

**Основной успешный сценарий:**

1. Разработчик выбирает тест-сьют для запуска.
2. Система проверяет доступность тестовой среды.
3. Разработчик подтверждает параметры запуска.
4. Система выделяет необходимые ресурсы.
5. Тест-раннер запускает выполнение тест-кейсов.
6. Система собирает результаты выполнения каждого теста.
7. После завершения всех тестов формируется отчет.
8. Разработчик получает уведомление с ссылкой на отчет.
9. Система освобождает ресурсы (опционально).

---

**Диаграмма последовательности (Sequence Diagram):**

```plantuml
@startuml
actor Developer
participant TestController
participant EnvironmentManager
participant ResourceManager
participant TestRunner
participant ReportGenerator
participant CISystem

== Инициализация тестовой сессии ==
Developer -> TestController : Запустить тестовую сессию(suiteId)
TestController -> EnvironmentManager : Проверить доступность среды
EnvironmentManager --> TestController : Среда доступна

TestController -> Developer : Запрос параметров запуска
Developer -> TestController : Подтвердить параметры (среда, конфигурация)

== Подготовка ресурсов ==
TestController -> ResourceManager : Запросить ресурсы(тип, количество)
ResourceManager --> TestController : Ресурсы выделены

== Выполнение тестов ==
TestController -> TestRunner : Выполнить тест-сьют(suiteId, envConfig)
TestRunner -> CISystem : Получить последнюю версию кода (опционально)
CISystem --> TestRunner : Код получен

loop Для каждого тест-кейса
  TestRunner -> TestRunner : Выполнить тест-кейс
  TestRunner --> TestController : Результат теста (успех/неудача)
end

TestRunner --> TestController : Все тесты завершены

== Формирование отчета ==
TestController -> ReportGenerator : Сформировать отчет(результаты)
ReportGenerator --> TestController : Отчет сформирован

TestController -> Developer : Отправить уведомление с отчетом

== Завершение сессии ==
TestController -> ResourceManager : Освободить ресурсы
ResourceManager --> TestController : Ресурсы освобождены

TestController -> Developer : Сессия завершена

@enduml
