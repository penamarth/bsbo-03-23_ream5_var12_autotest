# Правила предметной области: Система автоматического тестирования

## Даты внесения изменений

| Версия                     | Дата            | Описание                                                                                                                         | Автор    |
| -------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Черновой начальный вариант | 20 ноября, 2025 | Первый черновой вариант правил предметной области для системы автоматического тестирования. Будет уточнен на стадии развития.    | 5 группа |

## Бизнес-правила

_(См. также правила для данного приложения в дополнительной спецификации.)_

| ИД     | Правило                                                                                                           | Частота изменения                                                                               | Источник                                |
| ------ | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------- |
| ПРАВ1  | Любой тест может быть запущен только после успешной конфигурации тестовой среды и загрузки тестовых данных        | Средняя. Возможны изменения при поддержке новых типов сред (контейнеры, облако)                 | Логика работы EnvironmentManager        |
| ПРАВ2  | Все тест-кейсы создаются и выполняются программно через TestRunner                                                | Низкая. Возможны уточнения при добавлении новых типов тестов или интеграции с другими системами | Архитектурные требования системы        |
| ПРАВ3  | Запуск тестов возможен только при проверке доступности тестовой среды и корректности конфигурации                 | Средняя. Возможны изменения при внедрении динамического выделения ресурсов                      | Технические требования TestOrchestrator |
| ПРАВ4  | Результаты тестирования обрабатываются системой до формирования отчёта, с фиксацией статуса и логов               | Средняя. Возможны корректировки логики при поддержке новых форматов отчётов                     | Логика работы ReportService             |
| ПРАВ5  | Генерация отчётов инициируется автоматически после завершения тестовой сессии                                     | Средняя. Возможно изменение при переходе на реальное время или интеграцию с дашбордами          | Технические требования ReportGenerator  |
| ПРАВ6  | Ошибки тестирования (падение теста, недоступность среды, таймаут) должны обрабатываться и фиксироваться в системе | Средняя. В будущем возможно расширение типов ошибок или изменение формата уведомлений           | Логика обработки ошибок TestController  |
| ПРАВ7  | Система должна поддерживать отмену тестовой сессии до начала выполнения критических шагов                         | Средняя. Возможны уточнения при внедрении более сложной логики выполнения тестов                | Логика управления TestOrchestrator      |
| ПРАВ8  | Все тестовые запуски должны выполняться через защищённое соединение с системами CI/CD и репозиториями             | Средняя. В будущем возможна поддержка новых протоколов безопасности или шифрования              | Требования информационной безопасности  |
| ПРАВ9  | Система должна проверять доступность тестовых ресурсов и корректно обрабатывать ошибки выделения                  | Средняя. Возможны изменения при добавлении новых типов ресурсов (GPU, память)                   | Логика работы ResourceManager           |
| ПРАВ10 | Все изменения состояния тестов должны фиксироваться внутри системы для надёжности и последующего анализа          | Средняя. В будущем возможно расширение хранения состояния тестов для аудита и аналитики         | Архитектурные требования TestService    |
